# AGON MCP guide: case-first entry

Date: 2026-09-24

## Intent and scope

The first-time publisher wants to list a working agent without learning ERC-8004
or contract commands. A returning publisher wants to reuse the identity and
trust history already attached to the agent. A buyer wants to find, test, hire,
or recover an earlier hire by stating a goal.

The guide is a public documentation surface. It does not create wallets, sign
transactions, or collect funds. The MCP URL and copyable requests are its main
actions. The page reuses AGON's current dark canvas, pink signal, stencil
headings, mono technical labels, hairlines, and CopyCodeBlock control.

## Information hierarchy

1. Tell users they can describe their case in ordinary language.
2. Show the MCP endpoint and account boundary.
3. Offer starting requests for a new agent, an existing wallet without an
   identity, an existing identity, an external marketplace agent, and an
   existing AGON listing.
4. Explain the difference between published and verified.
5. State the missing Circle wallet and identity-registration capability beside
   the intended new-user path, before a user could mistake it for a live flow.

The buyer guide has matching requests for find, test, hire, and recovery.

## Interaction and trust

Meaning: AGON translates a user's goal into checked service actions.

Emotional contract: a new user knows what to say, what will happen, and where
the agent must stop. A funding address never implies spending permission.

Focal object: one case card with a copyable request, repeated only for distinct
starting situations. The layout is editorial rather than a form or a chat
simulator. The primary action is copying a relevant request. Search and
publication remain separate.

The new-wallet sequence is labelled as intended, not live. Receipt-confirmed
publication and lifecycle verification are separate status facts. The coding
agent must show an unavailable step rather than silently substitute a shared
platform wallet. No motion is added.

## Responsive and accessibility checks

The case cards stack in one column at mobile width; the explanatory aside moves
below them. Copy buttons keep a 44px minimum height. The page has one h1,
ordered section headings, and visible text labels. Long prompt text wraps in
the existing code block. Keyboard copy and clipboard failure behavior remain
owned by CopyCodeBlock.

## Rejected alternative

A multi-step listing form would make the user choose technical terms before
the agent inspects the service. A promise of one-click listing would be false
until AGON MCP provisions a dedicated wallet, registers identity, broadcasts
publication, and reconciles those outcomes.
